# InnoWing 空间证据工作台

完整的本地照片标注与离线证据处理工具。交付版包含 214 张原图、官方楼层底图、米制校准、房间名称来源、已生成的 OCR 候选及 Windows 便携运行环境。原有 `AI-chatbot-competition` 文件和代码没有被修改。

## 启动

Windows 64 位：将 ZIP **完整解压**到有写入权限的文件夹，双击 `start-workbench.bat`。浏览器会自动打开本地工作台。无需安装 Python、数据库或网页依赖；不需要联网即可标注、OCR、检索和导出。

请不要直接打开 `web/index.html`，它需要本包的本地服务。关闭浏览器不会停止后台服务；需要结束时运行 `stop-workbench.bat`。保存数据位于 `data/workbench.sqlite3`，不要在升级时覆盖自己已使用的数据库。启动时如默认端口 8765 被占用，会自动选择后续可用端口。

其他系统可以安装 Python 3.10+ 和 `requirements.txt` 后运行 `python server.py --open`。Windows OCR 是系统引擎；其他系统的本地 OCR 需要 Tesseract，也可直接导入 OCR 原文。

## 标注流程

1. 左侧按官方相册／小组原有文件夹浏览，或导入自己的图片文件夹；按状态、楼层、文件名和备注筛选。
2. 选择楼层，在地图“拍摄点”模式点出拍摄者位置。可以拖动蓝点调整，X、Y 以米显示。
3. 选择“朝向”，在图中点击拍摄方向或拖动箭头末端。也能输入角度。0°为图上方、90°为右方；**不是已确认的地理北向**。空值表示未知，0°是有效方向。
4. 可选填视野范围、仰拍／俯拍与俯仰角。目标点、目标区域和拍摄者位置分别记录；同一张照片可以标多个目标。目标可以关联同一实体 ID，并独立填写区域、定位可信度和备注。
5. 照片可放大平移，框选标牌等细节。地图可描绘覆盖区域，用两点测距；开放区／历史子区使用虚线提示。
6. 填写日期、照片类型、分组、标签及四类备注。修改后自动保存到磁盘，切换照片先等待保存。手动保存可选自动下一张；支持撤销历史版本。
7. 连续照片可复制上一张的位置、方向、备注或元数据，分别选择复用内容。勾选照片可批量设置日期、类型、楼层、区域、状态、分组和标签。
8. 通过“跨图关联”连接全景与近照、同一物体、连续拍摄照片。重要物体建立统一实体 ID，后续按实体去重。

“已标注”需要拍摄点和非空朝向；不能定位时使用“待确认”或“无法定位”。拍摄点／朝向存在不代表已经现场核验，可信度另行保存。改变有定位记录的楼层会清除原楼层位置、目标与范围，旧记录仍在历史中。

## 真实平面坐标与房名

尺寸来源：官方会员页 2020 路径的 G/F、LG/F 建筑／疏散图。名称优先使用有明确对应关系的官方 2023 活动图；保存 2020 图名、2023 名、来源链接、名称年代、别名及历史子区关系。没有独立官方房名的通行分段不会伪造房间名称。

- 共享轴网原点：**DA／D6**，X 向右、Y 向上，单位 m。
- 横向尺寸链：2030 + 6750 + 7000 + 8000 + 7000 + 7000 + 6750 + 2030 = **46560 mm = 46.56 m**。
- 纵向尺寸链：2030 + 10750 + 6000 + 4750 + 2030 = **25560 mm = 25.56 m**。D1→D2 为 2030，不是 2300。
- 两层分别按轴线控制点拟合 X／Y 比例，处理图片缩放。坐标与区域顶点同时保存像素值和米制值，网页缩放不改变实际记录。
- **用户接受毫米解释，单位仍待核验**；源图未找到明确的尺寸单位注记。这是名义图纸坐标，不是现场实测。手工读点约 1 px ≈ 5.3 cm，分区边界误差可能更大；轴线拟合残差不代表现场精度。
- 共 61 个空间／历史子区，按 `room_id` 关联真实父空间；子区数量不是独立房间数量。2023 合并空间的 2020 子区不表示当前仍存在对应隔墙。
- “地图与坐标”视图可查看全部控制点、官方房名对照、来源图片，并计算几何中心直线距离与分区边界最短间距。距离不是步行路线长度或安全净距。

房间名称可在“地图与坐标”表格点击“确认房名”，填写现场核对名称与依据。同一真实父空间的历史子区同步更新，保留官方原名；JSON 恢复也恢复这些名称，几何坐标不变。

详细依据见 `assets/calibration-notes.md` 与 `assets/map-calibration.json`。

## 离线数据处理

“证据与检索”支持：

- 本地 OCR、人工框选细节与可选的大图重叠切片；全图、细节框和切片分别保留来源和坐标。
- 视觉识别输出文字、可见物体、数量、颜色、材料、物体关系和不确定性候选。需要在“设置”填写 API 端点、模型及密钥。默认兼容 `AI-chatbot-competition` 的 Azure 网关，也支持 Bearer 认证的 Chat Completions 端点。
- 密钥只保存在服务进程内，或由环境变量提供；不写入 SQLite、JSON 或交付包。重启后需要重新填写，或配置环境变量。
- 人工核验候选、修改确认内容、拒绝或恢复待审核。原始 OCR／模型输出不会被确认内容覆盖；只将人工确认结果形成事实。
- 手动添加确认事实，建立实体和跨图去重。登记实体数不是房间完整物体总数；遮挡、未覆盖区域及位置冲突需继续核验。
- SQLite FTS5＋中文子串检索，可查官方房名、备注、OCR 原文及确认事实；候选状态可在照片证据区审查。
- 拍摄覆盖与补拍清单；按真实父空间聚合照片 ID，避免历史子区造成重复统计。
- 任务进度、失败报告、停止任务、服务重启后的中断提示、内容／模型／提示词／裁剪范围缓存；重跑复用已处理结果。

本次预处理：214/214 张原图已校验，214 张全图 OCR 成功，0 失败，OCR 全部保持待审核。没有代替使用者填写拍摄位置或确认事实。视觉识别真实服务未运行，因为未配置密钥；接口契约已用模拟响应验证。

## 导出、备份与比赛接入

页面右上角可导出 JSON、CSV、完整结构化 ZIP，或备份 SQLite。导入 JSON 备份前自动备份原数据库；要求已导入对应照片，并核对底图版本。恢复失败会回滚，不留下部分变更。

标注 ZIP 包含：

- `annotations.json`：照片元数据、人工标注、历史来源、实体、跨图关联、原始候选和确认事实；
- `annotations.csv`：方便查看的照片／位置／方向／备注表；
- `images.json`、`descriptions.json`、`spatial-chunks.json`：比赛图片构建器与检索索引的适配输入；
- `confirmed-facts.json`、`entity-report.json`、`coverage.json`：确认事实、实体去重与覆盖状态；
- `map-calibration.json`、`map-regions.json`、`region-distances.json`：坐标、真实房名与空间距离。

导出包不重复装入原图，图片路径相对于工作台根目录。完整应用交付 ZIP 则包含全部原图。检索文档包含有可信度标记的人工位置／朝向／目标与已确认事实，不把待审核模型文字当确认事实。

代码审阅和适配依据为 `jingtongxu9-web/AI-chatbot-competition`，固定公开 main commit `684cdfdea99c89d464137391450fd844a8b7dcd2`。原 main 图片构建器只有远程图片骨架；本工具提供独立适配脚本，不改原代码、原数据或原索引。

只导出比赛适配数据：

```text
runtime\python.exe -B scripts\export_competition.py
```

如需使用比赛仓库的 embedding 网关生成独立 Chroma 索引，使用已安装比赛依赖的 Python 环境、设置密钥，并运行：

```text
python scripts/export_competition.py --competition-root <AI-chatbot-competition路径> --build-chroma
```

该脚本只读导入比赛仓库的 `bot.llm.embed` 与 `bot.store.get_store`，索引输出到本工具 `data/spatial-chroma`；不会覆盖原有比赛索引。便携环境不包含 Chroma 和比赛的额外依赖。
